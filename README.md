🧠 How I Think About Data

I approach data work with a few core principles:
	•	Respect the data — don’t force it to say what it cannot
	•	Structure before scale — clean representations come before models
	•	Relative insight over absolute numbers — context matters more than thresholds
	•	Clarity over complexity — explainable systems beat clever ones
	•	Design is part of analysis — visualization is a thinking tool, not decoration

I treat analytics as a form of decision support, not just reporting.

🔁 My Typical Workflow
	1.	Understand the real problem (not just the request)
	2.	Inspect the data honestly (schema, scale, gaps, bias)
	3.	Choose representations carefully (points vs areas, raw vs aggregated)
	4.	Optimize for correctness first, then performance
	5.	Design visual outputs intentionally
	6.	Document assumptions and trade-offs
	7.	Keep repositories clean and reproducible

This workflow is consistent whether I’m working with:
	•	geospatial data
	•	analytics pipelines
	•	or AI-adjacent systems
